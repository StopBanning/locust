## 1. a-beta-can-report-itself: 26 of 26, carried
The new module is `core/src/diagnostic_log.rs`. It writes `locust-errors.log` in the data folder:
- **Rolling:** at 512 KB the log is renamed to `.1`, so there are at most two files. The line is still written if the roll fails.
- **Lines:** each line has a time, a label and the detail. An empty detail is written as `(no detail)`.
- **Panics:** a panic hook writes a line. A panic on the window's `main` thread is the native app's version of "the renderer died".
- **Engine child:** `start_engine` now watches the engine child, and an unclean exit writes `child-process-gone` with the reason and exit code.
- **Unresponsive window:** a watchdog writes `unresponsive` when a `poll` runs longer than 5 s, then `responsive` when it ends. An idle window never triggers it.
- **Startup:** the first line gives the version, platform, kernel release and packaged or development build.
- **Deleted missions:** deleted mission ids are kept in memory, and a history read that brings one back writes `deleted-mission-returned`.

Call sites:
- `main.rs` (additions only): `diagnostic_log::begin` runs before `App::new`, `poll` holds a busy guard, and `refresh_recent` checks each read.
- `sidebar.rs` `delete_conversation`.
- `trash_section.rs` `restore_one`. This one has no test.
- `engine_process.rs` `start_engine`.
- `feedback_dialog.rs`: Settings > Report a problem > **Show the log** now opens the file manager on the log through `file_menu::reveal_path`, instead of printing the path.

Tests are in `core/src/a_beta_can_report_itself_tests.rs` (17) and `src/ui/a_beta_reports_itself_tests.rs` (10).

Breaks, each restored and checked with cmp:
- Dropping `check_read` in `refresh_recent` failed the returned-mission and ids-never-prompts tests.
- Replacing `watch_child` with `drop(child)` failed `the_engine_child_dying_is_written`.

**Privacy.** Electron's `diagnostics.ts` records what happened, never what was said: no prompts, file contents, mission text, paths, workspace or home folder, and `uploadToServer: false`. The Rust side matches it like this:
- **Missions:** written by id only, accepting ids of `[A-Za-z0-9._-]`, 128 characters at most.
- **Panic messages:** kept only when they are a literal in Locust's source. A message formatted at run time is replaced by a sentence saying it was left out. Tests: `the_log_names_ids_never_prompts` and `keys_home_and_run_time_messages_stay_out`.
- **Keys:** every detail goes through `secrets::scrub_secrets`. The test key is built at run time.
- **Paths and names:** the home folder is written as `~`. The first line uses only the `uname` release, never the computer or user name. Test: `the_first_line_carries_no_path_or_name`.
- **Nothing leaves the machine:** the log is a local file with mode 0600 on unix, and there is no network code. Test: `panics_are_kept_on_this_machine_as_settings_says`.
- **Deleted list:** kept in memory only and forgotten on restart. Test: `the_deleted_list_is_in_memory_only`.

Two cases are mapped in a native way:
- "starts before the app is ready": the test reads `main.rs` for `begin(` before `App::new(`, as Electron's test reads its own source.
- "renderer died": a panic on the `main` thread.

## 3. a-streamed-batch-is-written-before-it-is-shown: 6 of 8
The new module is `core/src/long_answer_batch.rs`, used by `native.rs` `drive_runtime`:
- `message.delta` text is held for up to 50 ms, then written in one write and one sync.
- Any other event writes the waiting text first.
- Approval answers write the waiting text before the card's record.
- A failed batch write ends the run.

**Exact `ledger_write.rs` change:**
- `fn line` now calls a new private `fn lines(Vec<Value>)`. It keeps the 512 KB per-record and 64 MB per-file limits, with a single `write_all` and `sync_all`.
- New `pub fn append_all(&mut self, events: &[runtime::Event])` builds each event as `append` does, writes them in one call, advances the sequence numbers and fires the run-began callbacks.
- `append` is unchanged.

`native.rs` changes are in `drive_runtime` and its helpers only: `write_approvals`, `flush_approvals_after_text`, `write_text`, and the deadline check on each pass.

Break, restored and checked with cmp: a deadline check that never fires failed `a_lone_delta_is_written_when_its_window_ends`.

Left: the two cases that need a write still in flight while the loop goes on (new deadline after an approval flush, and one write in flight with backpressure). The native loop writes synchronously, so neither state exists.

One thing to know: in the real loop, Codex's next event waits up to 50 ms, so text can wait up to about 100 ms.
