# Duet: round 7 flake (24 Nov 2026, 07:31 UTC)

**Short version.** The flake is in the test, not the app. Branch `duet/stop-after-relay`, commit `0855e1e1`, from `exec/native-engine` 98574e7b. One file changed (+7 lines in `src/ui/window_drive_tests.rs`). Break proven. B and C are still in progress.

## Cause
`relay_stops_at_hop_cap_and_exchange_strip_stop_ends_live_run` waited until the engine and the pane said nothing was running, then called `settle`. The strip's Stop (`exchange-stop`) doesn't read the engine. It reads the window's own live list (`seen_live`, taken at each `poll`) and its last read of the runs (`exchange_strip::compute`). `settle` draws frames and never polls. So when the wait ended between two polls, after the engine had finished but before the window polled again, the Stop stayed drawn. In the app, the next poll clears it by itself, so there's no code gap.

## Fix (test only)
After the "cap=2 stops exchange" wait, one more `pump` that waits on the window's state:
`s.seen_live.is_empty() && !s.recents.is_pending() && s.ledger_summaries.values().all(|m| !m.running)`.
