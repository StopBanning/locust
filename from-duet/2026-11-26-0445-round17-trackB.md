## What changed in app code (beyond tests)

- **opencode_serve.rs** (row 3), each after opencode-serve-run.ts:
  - The stream counts as closed only once every record it carried is read. Paced reply text after the close was lost.
  - A prompt receipt must name this session.
  - No message is sent once the stream was lost while the session was being made.
  - A failed check while the stream is open is asked again.
  - A stop is never overtaken by a check's failure.
  - A check that is out when the stream closes serves for the close.
  - Status and message checks are bounded at 10 s as a whole. A pooled connection kept no read timeout, so a check that
    never answered held the run for good.
  - Imported parts are ordered by their clock within each step.
  - The deadline says "busy" or "unfinished" as Electron does.
- **opencode.rs** (row 2): a stopped OpenCode 2 run no longer also reports an `opencode.<code>` failure.
- **opencode_commands.rs** (row 6, new): `read_commands`, a port of `readOpenCodeCommands`. It starts a server in the
  folder with a random password and `OPENCODE_PURE=1`, reads `GET /command?directory=...`, and always stops the
  server. `RuntimeCommands::learn_opencode` keeps the list.
- **agents.rs `discover_one`** (row 7): OpenCode's version is asked first.
  - OpenCode 2 is checked by `acp --help` alone (new private `opencode_acp`), with no remembered help and nothing kept.
  - A major Locust doesn't run is refused after the version alone.
  - OpenCode 1 reuses that one version answer.
  - **Before this, an installed OpenCode 2 was asked `run --help` and its model list, and came out not ready.**
  - agents.rs is outside the files the round named for Track B, but it isn't on the keep-clear list. This was the only
    place to fix it.
- **kilo.rs** (row 8):
  - The git shim now points at the git PATH actually runs, or writes no shim when that git's path is unsafe. It used to
    skip ahead to a later, safe git, which made the child run a different git than PATH would.
  - `write_git_shim` takes the PATH it reads.
  - New private `command_at`, called by `command` (kilo.rs:131).
- Test-only seams: `Serve::records`, `with_recovery_budget`, `with_startup_budget`.

New public functions and their call sites:
- `opencode_commands::read_commands`: called by `RuntimeCommands::learn_opencode`.
- `learn_opencode` is **on the shelf**, like `learn_claude`. The window's `/` menu refresh
  (src/ui/runtime_commands_ui.rs poll) should call it, as Electron's `refreshListedCommands` does. Until then nothing
  fills OpenCode's list natively, so a typed `/review` reaches an OpenCode teammate as a plain message.

## Not carried, and why (gaps worth knowing)

- **Row 1:** "reports a record it cannot parse as a diagnostic". The server's SSE reader drops an unparseable `data:`
  record without a word (opencode_serve.rs `read_events`).
- **Row 2 (9 cases):**
  - The second queued turn and queued steering: the native OpenCode driver offers no steering.
  - Prompt-write exception, unacknowledged exit, listener-registration failure, failed permission reply, staged receipts:
    these need fault hooks inside `Acp` that don't exist.
  - Non-finite handshake option: there's no native option to pass.
  - Record overflow is held by the Acp output-limit tests instead.
- **Row 3 (2 cases):**
  - A stream read error is read natively as the end of the stream, so the run fails with the closed-stream reason, not
    the error's own words.
  - A prompt receipt arriving during a status check can't happen natively, because the receipt comes before any check.
- **Row 5:** "${sandbox}: the same permission config and environment as run". The native app has no `opencode run`
  route to compare with.
- **Row 6:** "is named on the command line, and its arguments are the message on stdin". Same reason: no `run` route.
- **Row 7:** "uses the executable's launch prefix and environment". A native launch is the found path alone. The check
  runs at that path on the same 10 s clock as every check, which the first case asserts.
- **Row 8:** "prefers git.exe over a git.cmd". This is Windows only. The git.cmd case is carried as the same promise for
  the `git` shim, and `git&.exe` as a `$` in the path.
- **Found while doing row 4:** native drops a permission reply when the stream has already run ahead to idle (the reader
  sets `own_end` before the engine answers). This is reachable only if a server goes idle with a request pending. The
  stand-in waits for each reply, as OpenCode's real server does. App code is unchanged.
