## What each row changed
1. **Reading the notifications (a06d7921).**
   - New `core/src/runtime/goal.rs` holds the types:
     - `ThreadGoal` has threadId, objective, status, tokenBudget?, tokensUsed, timeUsedSeconds, createdAt and updatedAt.
     - `GoalStatus` covers active, paused, blocked, usageLimited, budgetLimited and complete. Any other status, or one that is not text, reads as `Unknown`.
     - `GoalEvent` is either `Updated` or `Cleared`.
   - `from_notification` reads `thread/goal/updated` {threadId, goal} and `thread/goal/cleared` {threadId}. A goal with no objective, or a clear with no thread, reads as nothing.
   - `Normalizer::accept` passes both notifications to `goal_said`. A goal from another thread is ignored.
   - `Codex::standing_goal()` returns the goal the thread holds.
2. **Set, get and clear (11eafbd6).**
   - New `Runtime::goal(GoalAsk) -> GoalAnswer`. Its default answer is `NoStandingGoals`, so every runtime other than Codex keeps no goals.
   - Codex sends one of three requests on its thread once the thread exists:
     - `thread/goal/set` carries only the fields the person gave, plus `origin: "user"`. A status of `Unknown` is never sent.
     - `thread/goal/get`.
     - `thread/goal/clear`.
   - How each answer comes back:
     - **Method not found** comes back as `NoStandingGoals`. That means JSON-RPC code -32601, or Codex's "unknown variant \`thread/goal/..\`" words.
     - **Any other refusal** comes back as `Refused(Codex's words)`.
     - **Asked before the thread exists**: nothing is sent, and the answer is `NoThreadYet`.
     - None of these ends the turn.
   - `request_within` is now built on `answer_within_or_refusal`, which hands back the server's error object as it came. Existing callers behave as before.
   - The stand-in app-server can now refuse with a code of its own (`{"error": .., "code": ..}`).
3. **Ledger events and resume (3e6d216c).**
   - Each change writes one info `adapter.diagnostic`, shaped like the one `thread/compacted` writes:
     - `codex.goal_set`: "Codex holds a standing goal: …"
     - `codex.goal_status`: "Codex's standing goal is paused: …", "…ran out of its token budget: …", and so on.
     - `codex.goal_cleared`: "Codex's standing goal was cleared."
   - The set and status events also carry `goal`: the protocol's fields, with the objective scrubbed of secrets and capped at 4,096.
   - What does not write an event:
     - Updates where only the counts tick.
     - The notification that echoes our own set or clear.
     - A clear on a thread known to hold no goal.
   - A reopened conversation asks `thread/goal/get` after `thread/resume` and before `turn/start`. It learns the goal it holds without writing it again, so only what changed since gets written.
     - A fork does not ask, and neither does a new thread (it is known to hold none).
     - A Codex without goals lets the turn go on.
     - Goal requests wait 10 s at most.
   - Both fake app-servers now answer `thread/goal/get`. `commands-app-server.py` also takes `goal` and `goal_notices` in `commands-reply.json`.

## Left
- **The response shapes are taken from the brief; I could not check them.** I could not read the Codex protocol source from this session, because GitHub access is scoped to this repository. The code assumes the set and get answers carry `goal` (an object, or null on get), and treats the clear answer as opaque. If set answers empty, the event comes from the `thread/goal/updated` that follows instead.
- **createdAt and updatedAt are read as integers** (unix seconds, assumed). A string timestamp would read as 0.
- **No host path writes a set or clear made between turns.** A set or clear called once the turn has ended queues its event on a runtime whose drive loop has already returned. The goal card will need a path for that.
- **A reopened thread whose `get` fails** stays "unknown", so its next update is written as `codex.goal_set`.
- **The new info diagnostics are not filtered out of `activity_trace` notices** the way `.context_compacted` is. If the trace is shown, they would appear as notices. I left that for whoever builds the screen.
