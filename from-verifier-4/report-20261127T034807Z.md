What this adds to a full run: on the same binary, `cargo test -p locust-core --lib -- --skip soak_tests` took 125.1 s
of test time; the full run took 138.2 s on `09ee2377` and 134.9 s on `fae0e947`. So the soaks add **~10-13 s wall** to
the parallel suite, under the 20 s line. Serially they cost ~29 s, so a gate that runs one test per process without
parallelism pays the whole 29 s. cargo-nextest is not installed here.

Watch item, not a blocker: `long_conversation_list_short` (3x ratio of medians) and `many_turns_short` (RSS growth) both
measure timing or memory while the rest of the suite runs alongside. Both passed in both full runs. If either flakes on
a loaded gate machine, mark it ignored rather than widening its rule.

Every break built (none only stopped the build), and every file was restored byte for byte (`cmp` clean each time).

**B5, and the test added for it** (`fae0e947`). `burst_claude_records_short` uses a held reader, so the fake agent has
written all 50,000 records before anything is read. A reader thread that carries on past the overflow therefore leaves
no gap anyone could see. The lane's `bursts_long` covers the slow reader, but it is ignored (and fails on the ACP and
OpenCode faults). The added `burst_claude_records_slow_short` runs the same burst against the slow reader. Clean, it
stops at the bound with Electron's sentence and a whole prefix: 3 of 3 runs, 0.25 s, 2,172-2,248 records kept. With B5
it fails as shown in the table. Also noticed: under B5 the reader thread spins after EOF (it `continue`s past its
terminal record). No Claude-runtime thread-count soak would see that today, since row 1 drives Codex only.

## Faults the lane found in the engine (recorded as ignored, failing tests; not fixed, by the lane's design)

None of these blocks merging the tests, but each is a real follow-up:

- 2a: ACP stops at its bound without Electron's sentence.
- 2b: OpenCode 1's wording depends on whether the engine was busy when the burst came.
- 2c: ACP and OpenCode 1 read time grows with the square of the record count (19,000 chunks: ~46 s in the engine).
- 3: after a crash, a follow-up is refused as "still running" for 15 minutes, because `prior_of` never asks `orphaned`.
- 5: an open conversation's idle poll costs time in proportion to the whole conversation.

Fault 3 is the one a person will meet first.
