## Port onto round 1 and the M1 fixes

Every M2 change was re-applied on top of the new code, not copied over it. Nothing from the old M2 copy replaced a file that round 1 or the M1 fixes had changed. The two files with both kinds of change were merged by hand.

- `src/runtime/codex.rs`: the non-blocking stdin writer thread, `Control` watchdog, overflow terminate, and `kill_process` are untouched. M2 adds only: `Turn.resume` branch (`thread/resume`), `effort`, `with_cancel` / `cancelled()` (used by the handshake's `request` loop), and `interrupt_owed` / `send_interrupt` (a stop asked before the turn id is known goes out as soon as it is; `next_event` retries it while stopping). The interrupt still goes through the writer queue, so a blocked stdin cannot stall Stop: the independent watchdog kill from `stop()` is unchanged.
- `src/ledger_write.rs`: `open_checked` (O_NOFOLLOW + `Store::check_open_file`) is untouched and is still the only way a ledger file is opened. M2 adds `Continuation`, `create_continuing` (validated before the file is created) and the `continuesFrom` field. `create` delegates to it.
- `src/store.rs`: kept `check_open_file`; added `#[derive(Clone)]` and `electron()`.
- `src/ledger.rs`: round 1's tool drawers, plans, helpers, reasoning and secret scrubbing are untouched. M2 adds `pub(crate) metadata`, `Session::also_read` and the multi-folder `chain` scan. I did not touch `Item`, `ToolDetail` or `PlanStep`.
- `src/main.rs`: the 28 M2 edits applied by exact-match replacement into round 1's main.rs (none failed to find its anchor). Round 1's `activity_group`, `activity_item`, `disclosure`, drawer keys and its scenes (`thread-rich*`) are untouched. M2 adds two scenes, `native` and `native-live`.
- `scripts/fixtures/m1-app-server.py`: kept the M1-fix `M1_PID_FILE` and `flood` scenario; M2's resume scenarios are added on top and `flood` now reads `base` like the rest.
- `src/runtime/tests.rs`, `src/run_cli.rs`: the new `Turn` fields only. The M1-fix `sk-` test change is kept.
- `src/native.rs`, `src/native/tests.rs`: copied unchanged; they compiled against round 1 without edits.

## TypeScript functions ported

- `codex-app-server-run.ts:startCodexAppServerRun` (handshake): the `thread/resume` branch with `threadId` and `excludeTurns: true`, the same sandbox, approval policy and config as `thread/start`, and the model on the thread as well as the turn (0.864 note).
- `codex-app-server-run.ts`: the `effort` rule: only a plain `^[a-z]{1,16}$` word is sent.
- `codex-mission.ts:runtimeThreadIdOf`: the last `runtimeThreadId`; a `run.failed` with `sessionEnded` clears it.
- `codex-mission.ts:resumableThreadOf`: nothing after a session-ending failure or `host.folder_moved`; otherwise falls back to `metadata.continuesFrom.runtimeThreadId`. Ported as `native.rs:prior_of`.
- `codex-mission.ts:createMission` call (about line 2923): the `continuesFrom` shape for a follow-up (`reason: "follow-up"`, `checkpointEpoch: 1`, optional `runtimeThreadId`), written by `ledger_write.rs:create_continuing`.
- `mission-store/src/index.ts` `MissionContinuation`: the field set and its validation bounds (`missionId` a safe id, `runtimeThreadId` at most 2,048 characters).
- `teammate-store.ts:parsedFile`, `parsedTeammate`, `safeId`, `validName`, `validRoleTitle`, `isTeammateFolder`, `isTeammateRoute`, `isAccountId`: the roster read. A bad record is dropped; a file that does not parse, or has a schema other than 1, is unreadable and never "empty". Ported in `native.rs:parse_roster` and its helpers.
- `teammate-store.ts:createTeammateStore.read`: the 1,000,000-byte file limit, and a missing file reading as an empty team.
- `index.ts` (`workspace.json` read): the folder a teammate works in is its own `folder`, else the remembered workspace, else `~/Documents/Locust`.

The roster read is a deliberate subset: it keeps what the window shows and ignores the rest (avatar content, connectors, instructions and so on).

## What each point of the brief does

1. **Engine abstraction.** `native::choose` plus the `Kind` in `State`. The label is part of the status row.
2. **Teammates without Electron.** Roster read only. Non-Codex teammates are listed with "runs in Locust for now", Send is disabled for them, and `native::send` refuses them too.
3. **Continue.** `thread/resume` with the stored thread, and a new ledger file chained by `continuesFrom` to the conversation's newest turn. The conversation keeps its anchor id, as the door returns it. Recent and transcript read both folders, and native rows are marked.
4. **Stop.** `turn/interrupt` through the runtime, recorded as `run.cancelled` (transcript line "Stopped", not a failure). Stop appears only for turns in this process's registry. On native, `can_stop` ignores the window's `own_turn` flag unless `native::owns` agrees (tested with a forged flag).
5. **Off the UI thread, live.** The turn runs on its own thread. The window only tails the ledger file through the existing `Session` / `Tail` / `ledger_tick` machinery, so streaming goes through the same code as Electron's ledgers.

## Fixes after review (Codec's five findings)

Run from `m2b/native` with `LOCUST_TEST_TS_READER` set: `cargo test --release` gave **112 passed, 0 failed, 2 ignored** (was 104; the two ignored are the old live-Electron tests), three runs in a row. `cargo build --release` has no warnings. `python3 scripts/test-m1-cli.py` passed all five scenarios (success, failure, lost, interrupt, flood). The `native`, `native-live` and `thread-rich-open` snaps rendered without error to `~/work/scratch/m2-snaps/m2b-*.png`. I cannot view images, so none has been looked at. All checks are synthetic: no window opened, no real Codex turn.

1. **P1, stale tip.** `native::send` no longer takes a tip from the window (`Send.tip` is gone). It calls `real_tip(conversation)`, which walks the chain from disk in both folders at the moment of sending (`Session::chain_tip`, new, clears the header cache first). It then refuses with "A turn is still running in that conversation" if this process owns that tip or the tip's ledger is running (a turn from any process: fresh file, no terminal record), resumes the tip's own `runtimeThreadId`, and links `continuesFrom` to the tip. Tests: `a_stale_view_never_resumes_an_obsolete_thread_or_starts_beside_a_running_turn` (A completed, Electron's B running: refused, no ledger created; B finishes on a different thread: the follow-up resumes B's thread and links to B, with the fake rejecting any other thread id), `a_turn_running_in_native_blocks_a_send_from_a_stale_anchor_too`, and the window-level `a_stale_completed_pane_cannot_send_beside_a_turn_started_elsewhere` (the refusal shows in red and the draft is restored).
   - *Not an exact port.* In Electron the window sends the id of the turn it shows, and the host advances it before resuming (`codex-mission.ts`, `followUpOf = (await options.catchUpTerminal(named))?.latestMissionId ?? named`; `catchUpTerminal` itself reads the runtime's session file, `terminal-catch-up.ts`), then checks that turn is not active and resumes its thread (`resumableThreadOf`). I ported that order: advance to the newest turn, check it is idle, resume its own thread. The newest turn is chosen by the existing `Session` rule (the newest-modified child among descendants of the anchor), the same rule the window uses to show a conversation. Electron's own "is it running" check is in-process memory (`active`), which native cannot see; native uses ledger state (running means fresh within 15 minutes and no terminal record). A turn Electron runs that has not yet written its ledger file is invisible to native. Race: a turn that starts in the instant between the check and the file creation is not excluded.
2. **P2, ancestor race.** `Store::create_new_file_in` (new) walks the directory from `/` with `openat(O_DIRECTORY | O_NOFOLLOW)` per component, making missing directories with `mkdirat` relative to an already-verified descriptor, and creates the file with `openat(O_CREAT | O_EXCL | O_NOFOLLOW)` relative to the final descriptor. Each directory descriptor's device and inode is compared with Electron's folder and Codex's folders before it is used, so a swapped component is refused before anything is created. `ledger_write::open_checked` uses it; `check_open_file` stays after it as defence in depth. `swapped_ancestor_leaves_only_reported_empty_file` is replaced by `swapped_ancestor_is_refused_and_nothing_is_created_in_electrons_folder` (asserts the error and that Electron's ledger folder is still empty) and `a_symlink_in_the_final_directory_or_the_file_name_is_refused_and_creates_nothing` (a symlinked `mission-ledger` and a dangling final symlink into Electron's folder are refused, and the good path creates `0700` directories and a `0600` file exclusively). Unix only; other platforms refuse to create a ledger. Linux and macOS are the platforms with the descriptor-location check already.
3. **P2, Stop after reopening.** Native ownership is now the process registry, not the window's `own_turn` flag. `native_stop_key` (main.rs) takes the registry key for the pane's current tip or conversation (`native::owned_key`), and `can_stop` and `stop` use it on the native engine. Test: `stop_survives_reopening_an_owned_native_turn_from_recent` (start a long turn, switch teammate, reopen it from Recent, Stop is offered, stopping records "Stopped"). `stop_is_never_offered_for_a_turn_another_process_started` still passes, including its forged-flag case.
4. **P2, `~/.codex`.** `Store` carries Codex's folders (`$HOME/.codex` and `$CODEX_HOME` when set, absolute only) and `Store::check` refuses the root, every write path and the opened descriptor's resolved location when it is, or lies inside, Electron's folder or one of those. Symlinks and `..` are resolved first (the old standalone `guard` is gone). Tests: `codex_homes_are_refused_with_folders_inside_and_symlink_aliases` (the folders, descendants, `..` forms, symlink aliases, and that `.codex-native` and `<electron>-native` are still accepted) and `local_store_refuses_the_real_codex_home_from_the_environment` (`Store::new` with the real `HOME`).
5. **P2, blocking close.** `on_close` calls `native::shutdown_in_background`: it sets every turn's cancel flag and returns at once; a thread named `native-shutdown` watches for the turns to end (bounded at 8 seconds, and the runtime's own watchdog kills an unresponsive server after 5). `main` calls `native::wait_for_shutdown` after `App::run` returns, i.e. after the window is gone, so cancelled records can land before the process exits. Test: `shutdown_returns_at_once_and_cancels_in_the_background` (an unresponsive fake server; the call returns in under 200 ms, then the turn is recorded `run.cancelled`).
   - *Unconfirmed:* I did not open a window, so I have not seen that Rune's `run` returns promptly after the close button. If the process exit should not wait at all, drop `wait_for_shutdown` and accept that a cancelled record may be missing. In that case the next run still shows the turn as ended by the freshness rule, but not as "Stopped".
