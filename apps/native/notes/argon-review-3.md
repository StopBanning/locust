### Findings (Most Serious First)

#### 1. Hidden panel polls the MCP server every 3 seconds forever when a turn waits for approval (or stalls)
- **Lines:** [`hide`](file:///Users/locust/Documents/Locust/native-review/quick.rs#L100-L106), [`toggle`](file:///Users/locust/Documents/Locust/native-review/quick.rs#L108-L112), [`land_reply`](file:///Users/locust/Documents/Locust/native-review/quick.rs#L224-L249), [`focus`](file:///Users/locust/Documents/Locust/native-review/quick.rs#L312-L317)
- **Concrete failure:**
  When the user dismisses Quick Ask by clicking away ([`focus`](file:///Users/locust/Documents/Locust/native-review/quick.rs#L312-L317)) or pressing the global chord ([`toggle`](file:///Users/locust/Documents/Locust/native-review/quick.rs#L108-L112)), [`hide`](file:///Users/locust/Documents/Locust/native-review/quick.rs#L100-L106) sets `s.visible = false` and calls `app.hide()` without calling [`stop_watching`](file:///Users/locust/Documents/Locust/native-review/quick.rs#L93-L98).
  - If the turn in Locust hits an approval card ([`Reply::WaitingForYou`](file:///Users/locust/Documents/Locust/native-review/engine.rs#L64)), `read_reply` in [`locust-mcp-tools.ts`](file:///Users/locust/Documents/Locust/native-review/locust-mcp-tools.ts#L409-L415) returns immediately without blocking for `wait_seconds`, and [`land_reply`](file:///Users/locust/Documents/Locust/native-review/quick.rs#L233-L236) unconditionally schedules `request_reply(s, Duration::from_secs(3))` even when `!s.visible`. Because the panel is hidden, the user never sees the `"… is waiting for you in Locust"` notice, cannot press `Escape` to stop it, and the hidden process polls Locust's MCP server every 3 seconds forever.
  - Similarly, on [`Reply::Working`](file:///Users/locust/Documents/Locust/native-review/quick.rs#L229-L232), a stalled turn continues polling every 20.5 seconds indefinitely in the background with no visibility check or timeout.
  - Note also the inconsistency between dismissal keys: pressing `Escape` ([`key`](file:///Users/locust/Documents/Locust/native-review/quick.rs#L284-L289)) stops watching and hides, whereas pressing the global chord to close the panel ([`toggle`](file:///Users/locust/Documents/Locust/native-review/quick.rs#L109-L111)) calls [`hide`](file:///Users/locust/Documents/Locust/native-review/quick.rs#L100-L106) without [`stop_watching`](file:///Users/locust/Documents/Locust/native-review/quick.rs#L93-L98).

When they type a new question and press `Enter`, [`key`](file:///Users/locust/Documents/Locust/native-review/quick.rs#L301-L307) consumes the event and calls [`send`](file:///Users/locust/Documents/Locust/native-review/quick.rs#L179-L186), which silently returns early at line 181 because `s.flight.is_some()`. Neither does [`send`](file:///Users/locust/Documents/Locust/native-review/quick.rs#L179-L210) call [`stop_watching`](file:///Users/locust/Documents/Locust/native-review/quick.rs#L93-L98) to supersede the old flight, nor does the UI prevent or explain why `Enter` does nothing.
  2. **Unguarded `s.team.request` on every show:** Unlike [`load_team`](file:///Users/locust/Documents/Locust/native-review/main.rs#L156-L165) in `main.rs` (`if s.demo || s.team.is_pending() || s.flight.is_some() { return; }`), [`begin_show`](file:///Users/locust/Documents/Locust/native-review/quick.rs#L88-L90) unconditionally dispatches `s.team.request(...)` every time the panel is shown:

- **Concrete failure:**

When `s.sending` returns `Err(_)` at [`poll`](file:///Users/locust/Documents/Locust/native-review/quick.rs#L271), unlike [`restore_failed_draft`](file:///Users/locust/Documents/Locust/native-review/main.rs#L520-L528) in `main.rs`, `quick.rs` does not restore the unsent message into `s.draft`.
  2. Both [`poll`](file:///Users/locust/Documents/Locust/native-review/quick.rs#L271) (`Err(_) => engine_error(s)`) and [`land_reply`](file:///Users/locust/Documents/Locust/native-review/quick.rs#L247) (`Err(_) => engine_error(s)`) discard the `Err(words)` string from [`Engine::start`](file:///Users/locust/Documents/Locust/native-review/engine.rs#L147-L150) / [`Engine::reply`](file:///Users/locust/Documents/Locust/native-review/engine.rs#L158-L161) and replace it with [`UNAVAILABLE`](file:///Users/locust/Documents/Locust/native-review/quick.rs#L15-L16) (`"Locust isn't running, or 'Let your other AI apps use Locust' is off."`). #### 5. `s.visible` can desynchronize from actual panel focus/visibility on `toggle`
- **Lines:** [`toggle`](file:///Users/locust/Documents/Locust/native-review/quick.rs#L108-L131), [`focus`](file:///Users/locust/Documents/Locust/native-review/quick.rs#L312-L317)
- **Concrete failure:**
  [`toggle`](file:///Users/locust/Documents/Locust/native-review/quick.rs#L108-L131) tracks visibility solely through the manual `s.visible` boolean, and [`focus`](file:///Users/locust/Documents/Locust/native-review/quick.rs#L312-L317) only hides when transitioning to `!focused`. If `app.open()` shows the panel when macOS prevents it from becoming key (so it never gains focus), clicking outside never triggers `focus(s, false)` and the panel remains stuck on screen. Conversely, if the OS hides the panel without a focus-loss callback (or if `tx.activation_token()` is `Some` at line 125 and calls `app.activate(token)` without `app.open()`), `s.visible` stays `true` while hidden, causing the next chord press to call `hide(s)` instead of showing the panel.
