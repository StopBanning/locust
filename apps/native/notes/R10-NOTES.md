## Usage (not executed here)

From this copy:

```bash
CARGO_TARGET_DIR="$HOME/work/scratch/native-target-r10" scripts/bench.sh ./bench-out
```

`BENCH_SECONDS=N` changes the idle duration for both implementations. Use a fresh output folder for each comparison; the script rejects an existing `samples.json`. It needs the release binary built first. The native bundle is optional and is looked up next to the configured target directory, matching `bundle-mac.sh`. Allow approximately 2 minutes 36 seconds plus startup time for default sampling (three native windows, each 10 seconds warmup + 30 seconds CPU measurement + 2 seconds quit margin, then 30 seconds measuring the existing Electron instance). RSS still uses 30 samples at seconds 0 through 29 after each native first-frame output; native CPU endpoints are at approximately seconds 10 and 40. Electron RSS uses seconds 0 through 29 and CPU endpoints use seconds 0 and 30. Actual CPU wall durations are recorded rather than assumed.

## Measurement boundaries and unconfirmed behavior

- Confirmed in local source for the pinned Rune commit `39301f6793266450a057f270da06b048a689be96`: `App::accessory()` configures winit's accessory activation policy and disables activation ignoring other apps; `open_inactive()` propagates `with_active(false)` to creation; `MacWindowOptions::level` configures AppKit's window level. No unconfirmed API or new dependency was used.
- The start is entry to `main`, not OS process creation. Rune's `on_frame_drawn` executes after queue presentation and first-frame GPU completion, and excludes skipped/unchanged frames. It does **not** expose the actual Metal drawable presentation/physical scanout timestamp. `first_frame_ms` is therefore a post-present host observation; exact display latency could not be confirmed with these public APIs.
- A fully covered window can be occluded by macOS and Rune can skip its frames. No readiness/fallback timer is counted as a real frame. The script fails after 60 seconds without a drawn frame, and terminates only its own native child. A partially visible window may be necessary. Rendering while completely occluded is not guaranteed by the locked API.
- Focus preservation, window ordering, timed shutdown and the end-to-end benchmark have **not** been exercised: the requested window-opening benchmark commands were deliberately not run. No comparison numbers are claimed.
- Electron cold start is unavailable because its working instance cannot be relaunched. Electron contains real conversations, while native uses synthetic data, favoring native somewhat in the memory comparison. This caveat is included in the generated report and JSON.
- CPU is now `(sum of cumulative ps time differences) / measured wall seconds × 100`, using only PIDs present at both endpoints. Native starts its CPU interval 10 seconds after first-frame output to exclude startup. Electron processes appearing/disappearing between endpoints are excluded; endpoint-only PID lists are recorded, and the report states that this can undercount process churn. Cumulative `ps time` has limited precision. Raw `ps %CPU` is a labelled lifetime/recent-decay estimate and is not used for the CPU table metric. Summed RSS may count shared pages multiple times. Bundle sizes use `du -sk` allocated bytes; binary size uses file length. Native runs are sequential, followed by one Electron window, rather than simultaneous measurements.
- Ruby is `/usr/bin/ruby` with its existing JSON, Open3 and FileUtils libraries; tests use the system's existing Minitest. Compatibility avoids newer `filter_map` syntax/APIs.
- TypeScript, Cargo manifests/lockfile, engine code and bundle script were untouched. This copy has no Git metadata, so verification did not include a Git diff.
