# Desk 3: Rust Window Events vs Electron `DESK_EVENTS`

In Electron (`apps/desktop/src/main/index.ts:627-634`), `mirrorToDesk` wraps `window.webContents.send` so every message the main process pushes to its window also calls `deskHost?.mirror(channel, args)`. `DeskHost::mirror` forwards only when a browser holds the window (`DeskHost::active`) and `is_desk_event(channel)` (`core/src/desk.rs:436-450`, matching `shared/desk-calls.ts:354-359`) allows the channel.

In the native Rust window (`apps/native/src/main.rs`), the window does not receive push IPC messages from a separate main process; instead `main.rs::poll(s, now, tx)` polls the shared engine (`core/src/engine_api.rs`) and background jobs once per tick. Mirroring therefore observes state transitions at one place per poll tick (`phone_section::mirror_desk`, called as the last line of `poll` in main.rs) and calls `DeskHost::mirror` + `DeskHost::flush` for each matched channel, only while a browser holds the window. Nothing is read while no browser holds it; a browser just given the window starts from what the window shows then, and asks for the waiting cards itself (`replay: 'approvals'`), as in Electron.

The Status column says what `mirror_desk` tells today (Desk 3, row 2). "Told" rows are covered by the window tests in `src/ui/phone_section.rs` (`a_browser_holding_the_window_is_told_…`, `a_browser_that_does_not_hold_the_window_…`, `a_channel_is_desk_event_refuses_…`, `what_the_window_hears_between_two_polls_…`).

## Non-`DESK_EVENTS` (Window-Only)

Channels in `WINDOW_ONLY_EVENTS` (`core/src/desk.rs:453-470`) — such as `locust:github-sign-in-code`, `phone:anywhere-changed`, `terminal:event`, `voice-call:event`, `telegram:changed`, `discord:changed`, `slack:changed`, `account:changed`, `remote-mcp:changed` — are rejected by `is_desk_event` inside `DeskHost::mirror` and are never sent to a browser.
