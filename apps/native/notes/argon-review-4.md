### Findings

1. **`Tail::read_new` can panic with `u64` underflow after a truncation reset followed by an I/O error, and drops records/reset state on mid-poll read failures** — [`Tail::read_new`](file:///Users/locust/Documents/Locust/native-review/ledger.rs#L209-L251), [`Tail::poll`](file:///Users/locust/Documents/Locust/native-review/ledger.rs#L191-L201)
   - **Failure (panic):** When truncation is detected (`reset == true` at [ledger.rs:217-222](file:///Users/locust/Documents/Locust/native-review/ledger.rs#L217-L222)), `self.offset` is reset to `0` and `self.lines` is cleared, **but `self.marker` is not cleared**. If the subsequent read loop ([ledger.rs:237-246](file:///Users/locust/Documents/Locust/native-review/ledger.rs#L237-L246)) or final marker `read_exact` ([ledger.rs:251](file:///Users/locust/Documents/Locust/native-review/ledger.rs#L251), e.g. if the file shrinks again before line 251) returns `Err` while `self.offset < self.marker.len() as u64` (such as `self.offset == 0` with a 64-byte `self.marker` from before the reset), the next poll sees `meta.len() < self.offset` as `false` and `!self.marker.is_empty()` as `true`, and computes `self.offset - self.marker.len() as u64` (`0 - 64`) at [ledger.rs:212](file:///Users/locust/Documents/Locust/native-review/ledger.rs#L212) — panicking with integer underflow in debug builds or seeking to `u64::MAX - 63` in release builds.
   - **Failure (dropped lines and lost reset):** `self.offset` and `self.lines` are mutated inside the read loop ([ledger.rs:243-244](file:///Users/locust/Documents/Locust/native-review/ledger.rs#L243-L244)) before all reads and the final marker `read_exact` ([ledger.rs:251](file:///Users/locust/Documents/Locust/native-review/ledger.rs#L251)) succeed. If a later read or the marker read returns `Err`, [`Tail::poll`](file:///Users/locust/Documents/Locust/native-review/ledger.rs#L196-L199) discards the decoded `records` vector while keeping the advanced `self.offset`, permanently skipping those records on the next poll, and resets `self.reset = false` at the top of the next [`Tail::poll`](file:///Users/locust/Documents/Locust/native-review/ledger.rs#L192) before the caller ever clears its `Transcript`.

3. **Idle and errored conversations never stop polling, scanning the entire ledger directory and re-reading files every 2 seconds** — [`ledger_tick`](file:///Users/locust/Documents/Locust/native-review/main.rs#L266-L271), [`ledger_tick` error branch](file:///Users/locust/Documents/Locust/native-review/main.rs#L318-L326), [`ledger_tick` wake](file:///Users/locust/Documents/Locust/native-review/main.rs#L331-L343), [`Session::poll`](file:///Users/locust/Documents/Locust/native-review/ledger.rs#L578-L590), [`Session::chain`](file:///Users/locust/Documents/Locust/native-review/ledger.rs#L616-L641)
   - **Failure (finished conversation still polled forever):** When a conversation finishes (`!snapshot.running && pane.after_tip.is_none()`), [`ledger_tick`](file:///Users/locust/Documents/Locust/native-review/main.rs#L266-L271) still keeps `pane.worker = Some(worker)` and schedules `pane.due = now + 2.0` ([main.rs:341](file:///Users/locust/Documents/Locust/native-review/main.rs#L341)). Because the interval is 2.0s, every idle poll satisfies `at.elapsed() >= Duration::from_secs(2)` in [`Session::poll`](file:///Users/locust/Documents/Locust/native-review/ledger.rs#L578), so [`Session::chain`](file:///Users/locust/Documents/Locust/native-review/ledger.rs#L618-L641) runs `fs::read_dir`, `file_type()`, and `metadata()` across **every `.jsonl` file in `mission-ledger`** (and re-reads up to `HEAD = 1 MiB + 1` via `head()` for any `.jsonl` file without a cached `mission.created` header) every 2 seconds while idle. Then [`Tail::read_new`](file:///Users/locust/Documents/Locust/native-review/ledger.rs#L205-L251) opens the tip file, reads the 64-byte marker at `offset - 64`, reads 0 new bytes, and seeks back to `offset - 64` a second time ([ledger.rs:248-251](file:///Users/locust/Documents/Locust/native-review/ledger.rs#L248-L251)) to re-read the exact same 64-byte marker.
   - **Failure (error loop re-reads all ledger headers from scratch every 2s):** On any `worker.poll()` error, [`ledger_tick`](file:///Users/locust/Documents/Locust/native-review/main.rs#L318-L326) replaces `pane.worker` with a fresh `ledger::Session::new` and sets `pane.due = now + 2.0`. That discards `self.headers` and all reader byte offsets, so a missing or unreadable ledger causes `Session::chain` to open and `head()`-read every `.jsonl` file in `mission-ledger` every 2 seconds indefinitely (and if a transient error happens on a multi-file chain, it re-reads the entire ancestor chain from byte 0).

5. **Continuation chains can miss final lines of a parent file, never invalidate replaced headers, abort on a single unreadable directory entry, and jump to a sibling branch** — [`Session::poll`](file:///Users/locust/Documents/Locust/native-review/ledger.rs#L594-L606), [`Session::chain`](file:///Users/locust/Documents/Locust/native-review/ledger.rs#L616-L673)

If the parent already had `offset > 0` and wrote its final lines (or completed a half-written last line) during the same scan interval in which the child `.jsonl` file appeared, the parent is skipped and its final events are permanently missed.
   - **Failure (wrong branch selected):** [`Session::chain`](file:///Users/locust/Documents/Locust/native-review/ledger.rs#L646-L672) walks up from `self.anchor` to `root` and then walks down by picking the child with max `(modified, mission_id)` ([ledger.rs:663-668](file:///Users/locust/Documents/Locust/native-review/ledger.rs#L663-L668)). ### Top Three to Fix

1. **Fix [`Tail::read_new`](file:///Users/locust/Documents/Locust/native-review/ledger.rs#L209-L251) reset and error atomicity:** Clear `self.marker.clear()` whenever `reset` is `true` (and guard `self.offset >= self.marker.len() as u64` before subtracting at line 212), and do not lose decoded records or the `self.reset` flag if a read or marker update fails mid-poll.
2. **Untangle in-flight state across [`begin_ledger`](file:///Users/locust/Documents/Locust/native-review/main.rs#L192-L223), [`leave_ledger`](file:///Users/locust/Documents/Locust/native-review/main.rs#L225-L231), [`select_teammate`](file:///Users/locust/Documents/Locust/native-review/main.rs#L233-L248), [`send`](file:///Users/locust/Documents/Locust/native-review/main.rs#L453-L493), and [`poll`](file:///Users/locust/Documents/Locust/native-review/main.rs#L865-L970):** Detach any in-flight MCP/ledger requests when switching conversations, preserve the actual teammate ID on ledger sends (and restore unsent draft text if cancelled), and never pair a completed `s.sending` result for one teammate with a different teammate's `s.ledger` header/tip.
3. **Stop polling finished/errored ledgers and stop re-scanning the entire `mission-ledger` directory every 2s** in [`ledger_tick`](file:///Users/locust/Documents/Locust/native-review/main.rs#L250-L345) and [`Session::poll`](file:///Users/locust/Documents/Locust/native-review/ledger.rs#L574-L641): Stop scheduling wakeups once a conversation is finished (`!snapshot.running && pane.after_tip.is_none()`), keep existing `Session` state on transient errors instead of recreating `Session::new` every 2 seconds, and bound `after_tip` waiting so a follow-up that doesn't create a new child file cannot lock the UI forever.
